# Retained MIT/HDFS renewal experiment

This hosted-only fixture connects the independently qualified full rclone build prerequisite to the owned MIT KDC and retained HDFS client. It is an experiment, with every provider, application, vendor, and vulnerability acceptance flag false. A passing parser or build does not establish runtime renewal.

The six-case matrix runs original and context-patched rclone v1.75.2 binaries against renewable and nonrenewable short service tickets. It keeps one rclone daemon, its backend identity, and the original credential cache across actual service expiry, proves a fresh cache read is unavailable, cuts one owned RPC connection, and observes a bounded reconnect plus repeated listings.

The four strict-policy cases retain a five-second clock skew. Each request must arrive 6–20 seconds after the original service ticket expires. The patched renewable control must authenticate its renewal request with usage 7, receive error 32 (ticket expired), and then acquire an ordinary ticket. The original renewable control must receive usage-11/error-31 rejection followed by ordinary usage-7 acquisition. Both nonrenewable controls must acquire one ordinary ticket.

Two renewable cases additionally use the MIT default 300-second clock skew. Each request must arrive 1–15 seconds after service expiry, within that grace period. The patched case must produce exactly one authenticated renewal response with no fallback acquisition; the original binary must still produce usage-11/error-31 rejection followed by ordinary acquisition. Renewable requests must retain 25–59 seconds of the original renewal horizon. Timing is observed from the authenticated request and original ticket, without adjusting clocks. MIT documents renewal within clock-skew grace in [kinit](https://web.mit.edu/kerberos/krb5-1.20/doc/user/user_commands/kinit.html) and the [clockskew configuration](https://web.mit.edu/kerberos/krb5-1.20/doc/admin/conf_files/krb5_conf.html#libdefaults). Passing the grace-period case does not establish renewal beyond expiry plus grace.

The observer binds each TGS authenticator to its original ticket/session key and request checksum. It binds the decrypted reply to the nonce, identities, ticket times, renewable horizon, flags, and new key. It then binds the initial and fresh HDFS GSS/AP requests to the expected original and returned tickets, verifies the service authenticator under usage 11, observes the bounded SASL state sequence, and matches the exact empty listing response. RPC frames are forwarded unchanged. The established RPC parser has 85 managed vectors; authenticator, response, and service-AP mutation controls must pass during native execution.

The wrapper reuses digest-bound preparation workers from the complete rclone build and MIT prerequisite. Separate owned temporary roots preserve each worker's admitted path rules. Public source/module archives, Maven JARs, and MIT packages remain pinned and verified. Go and Java compilation run only in the pinned hosted image with networking disabled. Each of seven runtime containers (binary identity and six cases) has no network, read-only root, UID/GID 10001, all capabilities dropped, no added privileges, 128 PIDs, 2 GiB memory, two CPUs, and a 128 MiB private tmpfs. Java cases have a 180-second child timeout and a separate 195-second supervisor bound.

The qualified MIT owner and source template remain unchanged. A separately pinned owner copy changes only the two rendered clock-skew lines for the selected policy, verifies nine managed mutation vectors, and rechecks the exact private file identities and bytes before startup. Its exact child identity is the only process added to the original process baseline; all owned children, streams, threads, listeners, private files, containers, image, contexts, and raw logs must be accounted for and cleaned. Only closed, bounded JSON diagnostics are uploaded. Raw tickets, keys, RPC frames, KDC logs, dependency redirect URLs, and candidate binaries are never published.

Run pure checks with:

    python -I -S -B scripts/provider-lab/hdfs-kerberos-positive-renewal/run_guarded_tests.py

The audit hook rejects network, subprocess, native library loading, exec, and spawn attempts. Native qualification is performed only by the automatic pull-request workflow; there is no manual-dispatch entry point. Inspect the exact-head sanitized artifact independently before granting any further acceptance.

Credential flags are bound exactly to the synthetic MIT policy: the TGT has INITIAL, PRE_AUTH, RENEWABLE and ENC_PA_REP; service tickets have PRE_AUTH, TRANSIT_POLICY_CHECKED and ENC_PA_REP, with RENEWABLE only in that case. Issued and serialized flags must match. The TGT and both service-ticket values were observed in the four-case native run [42648905757](https://github.com/Donovoi/triage-with-rclone/actions/runs/42648905757). They agree with the upstream [MIT 1.20.1 flag construction](https://github.com/krb5/krb5/blob/krb5-1.20.1-final/src/kdc/kdc_util.c#L771) and [transited check](https://github.com/krb5/krb5/blob/krb5-1.20.1-final/src/kdc/do_tgs_req.c#L569); retained renewal remains unqualified. [RFC 6806 section 11](https://www.rfc-editor.org/rfc/rfc6806.html#section-11) defines ENC_PA_REP. Unknown or additional flags, forwarding, proxying and delegation remain rejected.

The response observer records at most four typed stage/error summaries. A failed renewal response keeps its own finite stage even if a later ordinary acquisition completes. No tickets, keys, identities, raw frames, or exception messages are added to diagnostics; the successful case still requires the exact expected response sequence.
