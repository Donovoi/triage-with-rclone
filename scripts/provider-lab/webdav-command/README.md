# WebDAV command protocol experiment

This default-off Linux experiment checks rclone1.75.2 command-based bearer tokens against one local test server. It does not test a Windows application or a real account. It cannot complete a provider ledger row.

The five cases require A,A,B renewal; the full default100 denied GETs and102 helper invocations after a failed refresh command; initial command exit70; successful empty command output leading to10 denied metadata requests and11 helpers; and transfer cancellation after two increasing correct incomplete content extents. No rclone retry, pacer or transport defaults are overridden. Cancellation is one SIGINT to the retained owned copy group after the content reader closes. Helper journal completions describe intended exits, not independent helper OS exits or parent linkage.

The four core modules run only through the separately verified image entrypoint. The image is pinned, stdlib-only and read-only. Every case owns its private `/work` control/config/output. The supervisor validates the actual created container before its sole start: network-none, UID10001, capabilities dropped, no-new-privileges, private namespaces, no mounts/ports/devices,64PIDs/512MiB/1CPU and one32MiB private tmpfs. Existing GCS code supplies the retained Docker command and cleanup pattern, under distinct names/labels. Unverified command lifetime prevents later resource cleanup. Cleanup failures cannot qualify a result.

The fixed build manifest is copied from the exact created container without starting it. Its interpreter hash is build evidence, not independent host hashing of the interpreter. The entrypoint separately hashes the actual in-container interpreter/runtime/source files before loading the core from source bytes; cached bytecode and unrelated module aliases are not accepted. Before execution, after cleanup and during independent validation, the supervisor binds its nine fixed input files to the exact Git commit using their tracked blob IDs and current SHA256 hashes. It binds both image records to these same source bytes. The unchanged runtime manifest and hash-verifying downloader supply the Linux executable.

Case limits are60/420/30/90/120s; the suite720s, final owned cleanup30s and container attach780s. These are new qualification bounds, not host-latency guarantees or changes to other tests. A failed or incomplete case is retained and is not retried. Successful fixture events are compared only after the owned fixture closes and joins. Preallocation or bytes sent alone cannot prove download progress.

Only manual `workflow_dispatch` with `webdav_command_experiment=true` and the exact `expected_sha` enables the job. It requires the existing revision/test/Python-audit jobs. It performs one supervisor run and a separate validation step even when the run fails, then uploads only the bounded normalized JSON. It adds no nightly requirement or ledger import. Raw Docker/RC output, configs, endpoint/token text, images and executables are not published. The immutable base image and shared Docker build cache are not pruned; only owned container/image/temp resources are removed.

Normal pure checks: `python -B -m unittest discover -s scripts/tests -p 'test_webdav_command_*.py'`. Author validation uses an additional process/socket/thread/native prohibition wrapper. No native Linux result has yet been obtained for this implementation; source and fake checks do not establish actual command counts, cancellation or cleanup.
