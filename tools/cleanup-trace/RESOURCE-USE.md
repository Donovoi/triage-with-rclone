# Optional post-failure resource-use observation

This private candidate adds no cleanup fix or ownership verdict. It is disabled unless the existing `runtime-cleanup-trace` feature is compiled, the existing hosted ARM64 authorization passes, and both `TRIAGE_RUNTIME_CLEANUP_TRACE=1` and `TRIAGE_RUNTIME_RESOURCE_USE=1` are supplied. There is no workflow change or new hosted qualification.

The exact PR115 unit is `ui::flows::download::tests::external_config_listing_selection_acquisition_preserves_source_and_checkpoint`. Its isolated source path owns one extracted runtime and one original removal, although it runs several child commands. The independent validator requires one completed failed unit (101), one primary record, one following supplemental record, and externally supplied exact source/runtime/library-harness hashes. Those hashes must be established by a separately reviewed trusted launch/selection path; this validator does not download, execute or independently hash binaries. The historical menu/CLI selectors remain unchanged and cannot silently stand in for this unit. Full-suite execution is outside this contract.

The original removal closure runs once and returns its original error unchanged. Only raw OS32 triggers the supplement, after the original survivor probe and ETW finish, before `private_fs::observe_residue`. The original finite trace write must return success. RM requires all existing session-start/STOP/absence/consumer-completed/consumer-closed/worker-joined flags and the prior probe's successful close. Correlation ambiguity, unsupported opcode or schema1168 does not by itself suppress this separate observation. An uncertain observer/probe close does suppress it. Neither the original trace, schema, ownership, cleanup nor test verdict is promoted.

Registration retains a bounded local DOS filename and original file identity/stamp from the extraction handle; it retains no file/process handle. The adapter accepts only the exact documented local-drive extended prefix, converts it to an ordinary full DOS filename below MAX_PATH, and rejects UNC/GLOBALROOT/relative/stream/dot-component/trailing-space forms. Identity checks before and after RM reject nonregular/reparse/multilink/replaced/changed files. Each read-attributes probe shares delete and is closed before the query. The pathname-based bracket is not atomic. Failed close remains uncertainty; there is no retry. Current-process PID and creation FILETIME come from the current-process pseudo-handle; no other process is opened.

Exactly one StartSession is allowed. After a successful Start, at most one RegisterResources registers one file and zero applications/services; at most one GetList uses 64 zero-initialized entries; exactly one EndSession is attempted, including failed registration/query. MORE_DATA, malformed counts/types/identities or duplicate process identities are unavailable rather than partial results. End failure and post-probe close failure take precedence and discard all counts. No RmShutdown, Restart, Cancel, process inspection, deletion, wait/retry, watchdog or abandoned thread exists. **RM APIs are synchronous and have no hard caller deadline.** A hung or killed call can leave the primary failure recorded but no valid supplement or proven RM teardown; it cannot pass. Output-write success is an API observation, not durable storage proof.

The `runtime_cleanup_resource_use=` record is at most1024 bytes including prefix/newline. It contains fixed labels/booleans, runtime hash, API status numbers, and admitted count/type buckets. Caller use requires equality of PID and creation time in memory; only a Boolean and remaining process count are emitted. Paths, PIDs, times, names, service names, session keys and raw exceptions are excluded. A current caller entry does not prove it caused OS32. Zero entries do not prove no conflicting handle, image reference or directory conflict existed. Types are unknown/main-window/other-window/service/Explorer/console/critical, in that order. Unknown future enum values reject rather than guess.

`validate_resource_use.py` retains the exact original trace and its digest in the bound result. Missing/duplicate/reordered/malformed supplementation cannot hide a valid original trace. The CLI returns1 even when resource-use observation is available because the original cleanup/test failed. This is not a provider or causal lock-owner acceptance path. Original std removal suboperation/target remain unknown; RM is a later applications/services resource-use snapshot.

Source tests: pure Python validator/privacy/order/negative checks run under socket/process/thread/native-loader guards. Rust fake call-sequence, error-injection, path and identity tests are compile-checked only; no native-capable test binary was executed. Compile-only x64 validation does not prove ARM64 linking or RM interoperability. A future separately approved hosted admission must select the real exact library harness, preserve all current gates, test the pure Rust model, and qualify a controlled retained-handle/control pair before relying on the native API. No calibration or workflow dispatch is part of this candidate.
